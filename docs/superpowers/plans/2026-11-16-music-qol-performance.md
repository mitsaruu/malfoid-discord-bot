# Музыкальный QoL и оптимизация

**Запрос:** страницы и кнопки очереди; выбор результата поиска; восстановление текущего трека после сбоя; кэш метаданных поиска; подготовка следующего трека; `/status`; отдельный музыкальный канал; больше ответов `/shar`; удаление `/welcome_channel`.

**Решения реализации:** продолжить Rust и SQLite. `/music_channel [channel]` с Manage Guild выбирает текстовый канал (без параметра снимает ограничение), настройки независимы от игр. Ограничение распространяется также на музыкальные кнопки; ветки выбранного канала разрешены. `/status` показывает безопасную диагностику без ключей и системных путей. Поиск `/play` по обычному тексту предлагает 5 вариантов, ссылки запускаются напрямую; выбор связан с автором. Восстановление возвращает текущий трек в начало очереди, без автоматического входа в голосовой канал; продолжение через `/resume`. Кэш на 10 минут хранит только безопасные метаданные и ссылки страниц, не прямые аудио-URL. Подготовка максимум одного следующего трека на сервер, с проверкой неизменности заявки. Никакого скачивания целых треков заранее.

**Приветствия:** пользователь подтвердил полное удаление приветствий. Команда, обработчик события, модуль и запрос Server Members Intent удалены; старые SQLite-данные не стираются.

## Шаги

- [x] Runtime: долговечная запись текущей заявки, атомарное восстановление, кэш TTL с ограничением размера/совмещением одинаковых запросов, подготовка следующей заявки.
- [x] Очередь: страницы, выбор удаления/перемещения со стабильным снимком и проверкой прав; защита чужих и устаревших кнопок.
- [x] Команды/диагностика: музыкальный канал, `/status`, варианты `/shar`, полное удаление приветствий по подтверждению пользователя.
- [x] Интеграция: общая проверка канала перед командами и кнопками, выбор обычного поиска, регистрация/help, документация/патчноуты.
- [x] Тесты функций и восстановления, полная сборка Linux в отдельном каталоге; ревью. Не пушить и не выкатывать без новой команды пользователя.
